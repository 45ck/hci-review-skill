# Comparing interface designs with quantitative HCI

Use this protocol to evaluate a specific change against the version people use today. The [model catalogue](interface-design-models.md) defines the inputs and formulas for each metric. The calculator consumes observations collected in a browser trace, a rendered fixture or a usability study.

## Plan the comparison

1. **Name the decision.** Record the task, versions, comparison unit, primary metric, direction and smallest worthwhile improvement before collecting data. For a metric with an approved target, compare distance to that target. Keep applicable standards and critical failure paths as separate checks.
2. **Match the conditions.** Use the same content, viewport, browser and font for render comparisons. In a repeated-measures study, give each participant both variants, counterbalance the order, and use equivalent tasks to limit learning. For traces, match scenario and environment, alternate build order, and reset state between runs. Record what changed.
3. **Choose one independent unit per pair.** Collapse repeat trials into one predetermined value per participant or independent test unit. A dozen frames from one trace or rerenders from one browser session supply detail about that unit. Fixed device and viewport matrices are deterministic coverage checks. Report them as coverage, with per-fixture deltas and failures.
4. **Preserve failed attempts.** Decide up front whether a timeout gets a capped duration, a failure outcome, or both. Keep denominators consistent and include no-action attempts where the task calls for them. Record dropped or missing pairs and their reasons. Check whether missingness clusters by version, device, input mode or participant group before interpreting the interval.
5. **Decide with the guardrails visible.** Compare the interval against the worthwhile gain, then review the separate safety, accessibility and task-outcome checks. An improvement on the primary metric cannot clear a failed guardrail. If you inspect many metrics or choose the endpoint after seeing the results, treat the findings as exploratory.

## Collection plan for the 20 models

The primary metric below is an example endpoint. Choose it only if it answers your task. Thresholds tied to product tokens, approved designs or baseline measurements need a recorded source and unit.

| Model | Matched unit and collection | Example comparison | Evidence to review alongside it |
| --- | --- | --- | --- |
| Kerning | Render the same glyph pair with kerning on and off. Hold script, font, size, variable axes, and other shaping features fixed. Measure advances along the writing direction. | `pair_adjustment_em` closer to an approved pair-specific adjustment. Analyse different reference pairs separately. | Blinded visual comparison at the actual display sizes. A negative adjustment can be intentional. |
| Optical centre | Rasterise the same icon and box at each supported size. Compute the alpha-weighted glyph centroid in the same coordinates as the box centre. | `normalised_centre_offset` lower as a geometric diagnostic. | Show randomly ordered offsets to users and capture the preferred alignment. A geometric result can disagree with perception. |
| Tabular numbers | Measure advances for digits 0–9 in the loaded numeric font. Measure separator anchors across mixed currency, sign and precision cases in the same column. | `decimal_drift_px` lower. Use zero or a tolerance justified by measurement resolution for the layout check. | Digit spread and position stability as a cell value changes. Include fallback fonts and actual locales. |
| Layout shift | Capture CLS per complete page-view measurement with Web Vitals instrumentation. For target drift, measure the same action target in matched lab scenarios under the same loading schedule. | `p95_target_drift_px` lower for matched groups of equivalent lab traces. | Compare field p75 CLS by device class as its own check. Retain post-input jumps and missed taps even when CLS excludes the movement. |
| Tracking | Measure computed letter spacing and font size for the same text role, script and style. Record the default and repeat with the text-spacing override. | `tracking_em` closer to the token for that text role. | Wrap, truncation, and control availability with text-spacing overrides. Check the actual fallback face and locale. |
| Optimistic update | Use one mutation ID per action to join input, first visible result, server settlement, and any visible correction. Exercise both build variants under the same network condition. | `feedback_ms` lower for the same type of mutation. | Correction rate, unresolved attempts, latest-intent state and recovery after timeout, rejection, or out-of-order settlement. |
| x-height | Measure the lowercase x from baseline to top of ink in the loaded face at a fixed CSS size. Test shipped sizes and zoom. | `x_height_ratio` closer to a legibility-tested type token. | Task-level recognition or reading performance. Choose script-appropriate measures for other writing systems. |
| Touch target | Probe the effective hit region, including clipping and overlays. Record movement distance and target width along the movement axis under a matched pointing task. | `predicted_movement_ms` lower using coefficients fitted for the same device and task. | Observed time and mis-taps. Review WCAG target size, spacing and applicable exceptions separately. |
| Leading | Measure consecutive baselines within the same text role after fonts load. Repeat across wrapping, zoom, and fallback fonts. | `line_height_ratio` closer to the calibrated value for that role. | Reading task accuracy and content or control loss under text-spacing overrides. |
| Origin-aware animation | Record the first visible animation anchor and the designated trigger anchor in one viewport coordinate system. Repeat with flipped placements near screen edges. | `normalised_origin_error` lower. | Trigger-to-popup association, keyboard focus, and complete operation in reduced motion. |
| OKLCH | Convert rendered, gamut-mapped swatches and actual composited foreground/backgrounds. Record target colour space and background. | `oklch_lightness_spread` lower for a palette designed to have uniform lightness. | WCAG contrast by role, including interactive states and transparent backgrounds. |
| Widow | Count multiline blocks and one-word final lines after layout using locale-aware word boundaries. Use the same text and width per variant. | `one_word_final_line_rate` lower. | Reflow, text overflow, and reading performance across widths, zoom, and translations. |
| Safe area | Measure both safe bounds and the complete hit rectangle in the same viewport coordinates. Test real notches, home indicators, orientations, and browser chrome states. | `minimum_clearance_px` must be non-negative in every applicable fixture. Use deltas to diagnose risky placements. | Keyboard overlap, scrolling to the action, and focus visibility. A median clearance can hide a single blocked checkout button. |
| Stagger | Record content readiness, first paint for each item, and when all items can be activated. Match list size, rendering load, and task. | `readiness_delay_ms` lower within the intended motion treatment. | Onset spread, availability of the first actionable item, and reduced motion. |
| Line length | Count graphemes per rendered full line after the font loads. Omit paragraph-final lines from this diagnostic and keep the same body text and script. | `median_graphemes` closer to a tested target for the script and viewport. | p90 line length and reading time with comprehension. Validate separately on narrow screens. |
| Affordance | Give equivalent, unprompted tasks and record each participant’s first action before the fixed timeout. Predefine which actions count as correct. | `correct_first_action_rate` higher per participant across equivalent tasks. | Completion, recoverability, and subgroup differences for keyboard and pointer users. |
| Combobox | Join input and rendered suggestions by query ID. Test correct selection, no matches, slow responses and out-of-order results. | `p95_input_to_results_ms` lower per independent unit with enough measured queries. | Correct selection, stale results, keyboard and screen-reader behaviour. Test against the WAI-ARIA pattern for the actual widget variant. |
| Interruptible animation | Interrupt at predetermined progress points and record when the motion first responds to the latest intent. Compare the old trajectory and retargeted position at a common timestamp. | `retarget_latency_ms` lower for matched interruptions. | Position jump, correct final state after repeated input, and immediate access with reduced motion. |
| Progressive disclosure | Use equivalent basic and advanced tasks with the same time cap. Fix the advanced-task share from usage evidence or test a plausible range. | `expected_task_time_s` lower with the same workload weights in both variants. | Basic success and advanced completion or discovery. Report both cohorts even if their average improves. |
| Shared element transition | Capture corresponding corners at the animated-to-live handoff. Use consistent coordinates, navigation input and destination-ready timestamps. | `handoff_error_px` lower on the same item and route. | Time to locate the item, destination readiness and focus, reverse navigation, and reduced motion. |

## Run a paired comparison

Copy the [synthetic example](example-comparison.json). Set `analysis` to `paired` for independent pairs drawn under a common study design, or `descriptive` for fixed fixtures and other comparisons without a sampling basis. Set the `model` to a catalogue ID and the `metric` to one of that model's calculator output keys. Use `higher`, `lower` or `closer-to-target` for `direction`. Supply a numeric `target` only for `closer-to-target`. Set `min_improvement` in the metric's units. For rates, a five-percentage-point improvement is `0.05`. Each pair has a unique study-local ID and the exact model inputs for `baseline` and `candidate`.

```bash
python3 -B docs/hci/models/compare.py docs/hci/models/example-comparison.json
```

Positive change means improvement. For `closer-to-target`, the gain is the baseline absolute distance from the target minus the candidate absolute distance. The output includes each pair, the median improvement, and, in paired mode, a two-sided interval for the population median. The interval uses binomial tails and ordered pair improvements. Under independent, identically distributed pair improvements, coverage is at least 95% and may be higher with discrete results or small samples. With fewer than six pairs the calculator returns no finite interval. Six is the mathematical minimum for this interval, and the sample size you need depends on precision and task variability.

| Decision | Interpretation |
| --- | --- |
| `meets-threshold` | The lower interval bound reaches the predetermined minimum. Review the other release checks before shipping. |
| `below-threshold` | The upper interval bound is below the minimum. The measured gain falls short of the chosen target. |
| `inconclusive` | The interval straddles the target or the sample cannot produce finite bounds. Report the observed effect and the uncertainty. |
| `descriptive` | Review the observed deltas and fixture failures. This mode omits the interval and threshold decision. |

The synthetic motion example returns a **19 ms** median improvement, an **11–22 ms** interval with at least **96.875%** coverage under the model assumptions, and `meets-threshold` against an 8 ms target. That target is specific to the example. Save the version IDs, raw observations, comparison JSON, result and guardrail outcomes with the [HCI scorecard](../templates/hci-scorecard.md).
