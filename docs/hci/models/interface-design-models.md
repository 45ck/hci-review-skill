# Quantitative models for 20 interface design terms

The [source reel](https://www.instagram.com/reel/DfknF2ljIE6/) supplies the terms and their order. The reel index below uses approximate start times. The models below specify what to measure, what the number means, and where a user outcome needs separate evidence. All example values are synthetic.

Run every example with Python 3.9+ from the repository root:

```bash
python3 docs/hci/models/measure.py docs/hci/models/example-measurements.json
```

Pass a JSON object keyed by model ID with the input fields shown in the [example file](example-measurements.json). Omit models outside the task. Use `-` as the filename to read the object from standard input. The calculator consumes measured values. Collect browser traces, geometry or usability observations first.

## Model catalogue

| Reel time | Reel term and model ID | Quantitative model | How to measure and interpret it |
| --- | --- | --- | --- |
| 00:00 | Kerning · `kerning` | Pair adjustment in em = (advance with kerning − advance without kerning) / font size. For example, (30 − 32) / 20 = −0.10 em. | Shape the same pair twice with the same font, size, axes and script, toggling kerning only. Use the pair advance along the writing direction. The sign shows whether kerning tightens or loosens the pair. Judge visual quality on representative pairs at the actual size. |
| 00:01 | Optical centre · `optical-centre` | Residual imbalance proxy = Euclidean distance from the adjusted ink centroid to the container centre, divided by the container's short side. For example, 1 / 32 ≈ 0.0313. | Compute an alpha-weighted ink centroid from the rendered icon and express both points in the same CSS pixel space. Compare candidate offsets with a blinded preference check. Ink balance is a geometric proxy for perceived centring. |
| 00:02 | Tabular numbers · `tabular-numbers` | Digit spread = max advance − min advance across digits 0–9. Decimal drift = max decimal-anchor x − min anchor x across rows. For example, 0 px and 0 px. | Measure actual glyph advances in the rendered numeric face and separator positions in a common column coordinate system. Try multiple digit counts, signs, currencies and locales. Equal digit widths allow stable updates and require decimal alignment separately. |
| 00:03 | Layout shift · `layout-shift` | Field CLS target ≤ 0.10 at the 75th percentile. For a lab trace, a shift score is impact fraction × distance fraction. CLS is the largest eligible session-window sum. For example, p75 CLS 0.12, p95 target drift 36 px. | Collect one browser CLS value per completed page-view measurement and segment field results by device class. Use the Web Vitals session-window rules. Also measure movement of the actionable target between its initial position and activation, including shifts CLS excludes after input. |
| 00:04 | Tracking · `tracking` | Tracking in em = computed letter spacing in CSS px / font size in CSS px. For example, 0.48 / 16 = 0.03 em. | Compare tracking across sizes using computed styles and inspect wrapping for the real scripts and strings. Apply all WCAG text-spacing overrides together to check for lost content or functionality. The 0.12 em override is a test condition. |
| 00:05 | Optimistic update · `optimistic-update` | Feedback latency = first visible result − action. Confirmation gap = server settlement − first visible result. Correction rate (the calculator’s `reconciliation_rate`) = rolled-back or corrected mutations / settled mutations. A negative confirmation gap means the server settled before the first visible result. For example, 40 ms, 440 ms, 3%. | Correlate each action, painted state, settlement and reconciliation by mutation ID. Sample normal, offline, rejected and out-of-order responses. Review p95 feedback latency and reconcile every terminal outcome to the latest authoritative state. |
| 00:06 | x-height · `x-height` | x-height ratio = lowercase x-height / font size. For example, 8.8 / 16 = 0.55. | Measure the lowercase x above its baseline or use the instantiated font's x-height metric. Hold size and rendering conditions constant between faces. Compare reading accuracy or speed at the intended sizes and include script-appropriate metrics for other writing systems. |
| 00:07 | Touch target · `touch-target` | Fitts' law index of difficulty = log₂(1 + D/W), with distance D and target width W along the movement axis. Predicted movement time = a + b × index. For example, 96 / 48 gives 1.585 bits and 175.1 ms using a = 80 ms and b = 60 ms/bit. | Measure the effective hit region and pointing distance in CSS px. Fit coefficients on representative tasks and devices, then observe miss rates. Separately check WCAG 2.2 AA SC 2.5.8 against the 24 × 24 CSS px minimum and applicable exceptions. |
| 00:08 | Leading · `leading` | Line-height ratio = baseline distance / font size. For example, 24 / 16 = 1.5. | Measure adjacent baselines in a consistent text block. Test wrapped paragraphs, fallback fonts and zoom. Verify that WCAG text-spacing overrides leave all content and controls usable. |
| 00:09 | Origin-aware animation · `origin-aware-animation` | Origin error = distance from the first visible motion anchor to the trigger anchor / trigger diagonal. For example, 5 / 50 = 0.10. | Define matching anchors for both elements in viewport coordinates before recording. Sample the first visible frame and compare a few trigger positions. Test focus, instant activation under reduced motion, and users' ability to associate the popup with its trigger. |
| 00:10 | OKLCH · `oklch` | Palette lightness spread = max rendered OKLCH L − min rendered OKLCH L. WCAG text contrast = (Y lighter + 0.05) / (Y darker + 0.05), using relative luminance Y. For example, lightness spread 0.02 and 5:1 contrast. | Measure palette values after target-gamut mapping and obtain luminances from the actual composited foreground/background pair. Use the WCAG contrast criterion for the text type. Matching OKLCH lightness is a palette comparison and has no automatic contrast implication. |
| 00:11 | Widow · `widow` | One-word final-line rate = multi-line blocks whose last rendered line has one word / eligible multi-line blocks. For example, 6 / 40 = 15%. | Count rendered lines with locale-aware word segmentation at representative widths, font sizes and translations. This is the reel's single-word paragraph ending. Check readability and layout after any change. |
| 00:12 | Safe area · `safe-area` | Minimum clearance = min(left, top, right, bottom margins between the actual hit bounds and the safe rectangle). A negative result means the target crosses an edge. For example, 16 px minimum. | Express both rectangles in viewport CSS px and test real device orientations and browser chrome states. Use reported safe-area insets to build the safe rectangle. Evaluate keyboard occlusion separately. |
| 00:13 | Stagger · `stagger` | Onset spread = latest first visible frame − earliest first visible frame. Readiness delay = time all items become usable − time content is ready. For example, 105 ms spread and 180 ms readiness delay. | Record paint and interaction availability independently. Vary list length and test reduced motion. Keep keyboard and pointer availability within the task budget. |
| 00:14 | Line length · `line-length` | Median and 90th percentile graphemes per full line, with spaces counted. For example, median 63 and p90 74. | Measure rendered lines and omit paragraph-final lines from this diagnostic. Compare reading time and comprehension across widths. Treat 65 as a candidate, and evaluate WCAG's separate Level AAA presentation requirement where applicable. |
| 00:15 | Affordance · `affordance` | Correct first-action rate = attempts whose first action uses the intended control / eligible unprompted attempts. For example, 34 / 40 = 85%. | Give representative participants a goal with no hint about the control. Record the first action, including no action by a predeclared timeout as a failure. Test keyboard and pointer cohorts. The metric evaluates discovery of the visual or semantic signifier. |
| 00:16 | Combobox · `combobox` | Correct completion rate = correct selections / attempts. Report p95 input-to-current-results paint and stale-result rate per eligible query. For example, 90% completion, p95 160 ms, 0% stale queries. | Start a timer at input and stop at the first paint for the matching query ID. Include slow and out-of-order responses and report missing results with the task outcomes. Verify focus, keyboard behaviour and announcements against the relevant APG pattern. |
| 00:17 | Interruptible animation · `interruptible-animation` | Retarget latency = first frame following the new destination − new input. Position jump = distance between sampled positions immediately before and after retarget. For example, 16 ms and 1 px. | Interrupt at several transition points. Sample both positions at the retarget timestamp with animation instrumentation to isolate discontinuity from normal frame-to-frame movement. Compare p95 latency, check the final state matches the latest input, and check reduced motion. |
| 00:19 | Progressive disclosure · `progressive-disclosure` | Expected task time = (1 − p) × mean basic time + p × mean advanced time, where p is the advanced-task share. Compare advanced completion rate separately. For example, 80% × 20 s + 20% × 50 s = 26 s, with 90% advanced completion. | Estimate each mean under the same predefined policy for timed-out and failed trials. Measure basic and advanced tasks before and after, including errors and abandonment. Use an observed task mix or run sensitivity analysis across plausible values of p. |
| 00:20 | Shared element transition · `shared-element-transition` | Handoff error = max of Euclidean displacements of matching corners between the last animated box and first live destination box. Task latency = destination ready − navigation input. For example, 2 px and 220 ms. | Use screen-space corners in consistent order. Check object identity and destination focus through open, back and interrupted navigation. Compare time to locate the item and preserve the same result with reduced motion. |

## Record evidence in a review

Use the [evaluation protocol](evaluation-protocol.md) for model-specific collection steps and paired comparisons. The [Chromium benchmark](browser-benchmark.md) provides runnable examples for 11 models.

1. Record the task, variant, device or viewport, input mode, accessibility settings and measurement boundaries.
2. Record sample sizes and eligibility rules. Report missing observations and failure rates with timings. The calculator uses nearest-rank percentiles and expects non-empty samples.
3. Compare the same tasks before and after. Use paired or counterbalanced trials where appropriate. Segment results when inputs or populations differ.
4. Define release targets from the applicable standard or the task baseline. For diagnostic proxies, record the user outcome that will confirm the design change.
5. Add findings to the [HCI scorecard](../templates/hci-scorecard.md) with a trace, task log or screenshot and a link back to the model.
