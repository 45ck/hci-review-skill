## Dimension observations

Record what was observed and its effect on the task. Use **observed**, **not assessed** or **not applicable** for coverage. For an observed issue, assign its severity using the task-specific definitions below; **none observed** means no issue was found in this scope, not universal conformance. Leave unassessed severity blank.

| Dimension | Observation and evidence | Coverage | Task effect / severity |
| --- | --- | --- | --- |
| Purpose and next action | Can someone identify the goal and an appropriate first action? Distinguish an unprompted task observation from a reviewer's expectation. | | |
| Navigation and return | Current location, reachable destination, preserved context and return path. | | |
| Terminology and copy | Consistent object/action names; useful descriptions; specific constraints and recovery copy. | | |
| State visibility | Pending, accepted, refused, canceled and completed states match host data. | | |
| Error prevention and recovery | Invalid actions are refused; useful work is retained where promised; retry/undo behaves as described. | | |
| Recognition and hierarchy | Relevant objects and actions are findable without memorizing hidden paths. | | |
| Cross-screen and input consistency | Meaning, state and access survive navigation, keyboard/agent use and responsive presentation. | | |
| Failure and accessibility coverage | Empty, loading and error states; content expansion, focus, reading order and applicable preferences. | | |

| Severity | Basis for this task |
| --- | --- |
| Blocking | Prevents the defined successful result or fails an essential guardrail. Name the failing step and evidence. |
| High | The task remains possible, but an observed error, costly workaround or recovery problem materially affects it. Describe the impact. |
| Low | A bounded clarity, consistency or presentation issue with no observed loss of the required task behavior. |
| None observed | No issue was found in the recorded scope. State what was actually checked. |

These are review judgements, not a validated numerical scale. Do not sum dimensions into a readiness score. A prototype can be studied to resolve uncertainty before all issues are fixed; document any task that cannot meaningfully be attempted.
