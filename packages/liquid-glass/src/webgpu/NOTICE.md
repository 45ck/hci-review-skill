# Liquid Glass renderer provenance

This renderer adapts the signed-distance lens, separate RGB samples, Fresnel approximation and edge-lighting approach from [arya3d/liquid-glass-webgpu](https://github.com/arya3d/liquid-glass-webgpu), commit `90cb73931bbaf38bd54b3263cd3fda1daef1869c`, linked by the user's [reference video](https://www.youtube.com/watch?v=lq-ikfNVx7g).

Copyright © 2026 arya3d. The complete [MIT notice](../../LICENSES/arya3d-MIT.txt) must accompany redistributed substantial source portions. The original attribution credits Inigo Quilez for rounded-box distance and Christophe Schlick for the Fresnel approximation.

The kit changes the original single-pill shader into instanced rectangular DOM surfaces, uses measured CSS radii and clipping, supplies a transparent premultiplied output, and shares a GPU device/pipeline across the viewport and top-layer popup canvases. Local rounded-box normals now displace the backdrop within a bounded bevel, replacing the earlier whole-face contraction. The flat face samples the supplied image in place. Separate RGB samples, warm and cool directional rim lights, pointer-driven meniscus and damped contact waves provide the optical response. Popup pixels include the light 42% material tint because their local canvas paints above the host's CSS background; normal viewport surfaces receive their tint from the live DOM. Optical edge-lighting remains above the tint. This is adapted source, not the unchanged reference shader or Apple's own implementation.

The user-provided Nimbus liquid navbar / Waterline example by guglielmogiannattasio.it informed the directional lighting, contact meniscus and ripple treatment. The user-provided Coffee Pour Menu by Aakash Mehra informed the damped selection motion and stop-when-settled animation scheduling. Their complete components and interaction engines were not transplanted: genuine UI SDK indicators, selection, keyboard handling and agent state remain in control. The local motion implementation shares a spring response with stiffness 420 and damping 34 across pointer and press feedback; the stylesheet animates the SDK's measured selection geometry.

Only the explicitly supplied backdrop is captured with html2canvas-pro. Live SDK controls retain DOM semantics above the optical layer. Capture is refreshed after backdrop mutation or resizing, or through `refresh()`. Pointer and ripple frames reuse the current texture and cached surface bounds. Layout/state changes, scrolling and actual geometric CSS transitions invalidate the bounds. One shared animation scheduler stops once springs, up to four active contact waves, selection travel and pending layout settlement finish. Hover and focus may retain a static highlight without an idle animation loop. The same bounded CSS hooks remain available when WebGPU is unavailable.

The provider defaults to `motion="system"` and `transparency="system"`. System reduced motion keeps static optics and suppresses decorative motion. Explicit `motion={true}` is an app-specific opt-in, while `false` turns motion off. Explicit `transparency="glass"` overrides reduced transparency for the app, and `"solid"` selects the readable fallback. Forced colours always suppress the GPU material. These choices do not alter device settings. WebGPU absence or errors are reported truthfully.

The current budget is 256 visible surfaces and a device-limited pixel ratio capped at 2. Background capture is a snapshot and cannot reproduce arbitrary live videos, protected cross-origin media or unsupported DOM/CSS features. One provider owns a document. Screenshot and automated interaction evidence cannot establish human usability or exact optical equivalence.
